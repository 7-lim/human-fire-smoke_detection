# Fire / Smoke / Person Detection — YOLOv8 Pipeline

Real-time detection of **fire**, **smoke**, and **people** in surveillance-style
video, powered by a fine-tuned **YOLOv8m** running on a CUDA GPU.

This project supersedes a classical-CV prototype (MOG2 + HSV thresholds + contours)
that lived previously in `Fire_Smoke_Detection.ipynb`. The preprocessing logic
from that notebook (video loading, frame inspection, colour-space EDA, blur
filtering) is retained in `notebooks/preprocessing.ipynb`. Everything from frame
sampling onwards now runs through a YOLOv8 stack.

---

## Pipeline at a glance

```
data/raw/          videos in fire/, smoke/, mixed/ subfolders
       │
       ▼  notebooks/preprocessing.ipynb  →  src/extract_frames.py
data/frames/       letterboxed 640×640 JPEGs, blurry + duplicate frames dropped
       │
       ▼  notebooks/auto_label.ipynb    →  src/auto_label.py
data/labels/       YOLO .txt labels per frame (COCO-person + HF fire-detector)
       │
       ▼  src/dataset_builder.py
data/dataset/      train / val / test split (75 / 15 / 10, grouped by source video)
configs/dataset.yaml
       │
       ▼  notebooks/training.ipynb      →  src/train.py
models/best.pt     fine-tuned YOLOv8m weights
       │
       ▼  src/inference.py
outputs/           real-time webcam, video, or single-image annotation
```

## What's NOT in the repo (and how to get it)

The following directories are intentionally git-ignored — they are either large,
user-supplied, or regenerable from the pipeline:

| path | what it holds | how to get it |
|---|---|---|
| `data/raw/` | source videos (fire / smoke / mixed) | Download the [Fire & Smoke Dataset](https://www.kaggle.com/datasets/unidpro/fire-and-smoke-dataset) from Kaggle, drop videos into `data/raw/{fire,smoke,mixed}/` |
| `data/frames/`, `data/labels/`, `data/dataset/` | extracted frames + auto/manual labels + split | Regenerated by running `preprocessing.ipynb` → `auto_label.ipynb` |
| `runs/` | YOLOv8 training artifacts (checkpoints, plots, metrics) | Regenerated by `training.ipynb` / `python -m src.train` |
| `models/best.pt` | promoted best weights | Either retrain (see step 5 below) or attach to a GitHub Release |
| `outputs/` | annotated videos / snapshots / labeling reports | Regenerated by inference / labeling runs |
| `*.pt`, `*.onnx`, `*.engine` | any model weights | auto-downloaded (ultralytics) or built by training |

> **First-time setup order:** clone repo → install requirements → drop videos
> in `data/raw/` → run the 3 notebooks in order. The pipeline produces
> everything else.

```bash

python -m venv venv

source venv/bin/activate

pip install --upgrade pip

```

### 2 · PyTorch with CUDA

`pip install torch` from PyPI usually installs the CPU build. For GPU
acceleration, **install the matching CUDA build first**:

```bash
# Example: CUDA 12.1
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

Then verify:

```bash
python -c "import torch; print('CUDA:', torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else '')"
```

### 3 · Register the Jupyter kernel (optional)

```bash
python -m ipykernel install --user --name=fire-smoke-yolo --display-name="Python (fire-smoke-yolo)"
```

## Step-by-step usage

### Step 1 — Extract frames

Open `notebooks/preprocessing.ipynb` and Run All. It walks through video EDA
and then calls `src.extract_frames.extract_frames_from_dir(...)` to fill
`data/frames/`.

Or run it directly from the CLI:

```bash
python -m src.extract_frames \
    --input  data/raw \
    --output data/frames \
    --sample-rate 10
```

### Step 2 — Auto-label

Open `notebooks/auto_label.ipynb` and Run All. The notebook:

1. Decides 3-class vs merged 2-class schema (based on fire/smoke frame ratio).
2. Loads `yolov8m.pt` (COCO) + `betasecond/jimei-fire-smoke-yolo` (Hugging
   Face — classes `Fire` and `Smoke`). The model id originally in the spec
   (`keremberke/yolov8m-fire-detection`) was deleted from HF by its author;
   the replacement here exposes the same class schema.
3. Writes YOLO `.txt` files to `data/labels/`.
4. Plots class balance + confidence histogram.

CLI equivalent:

```bash
python -m src.auto_label \
    --frames data/frames \
    --labels data/labels \
    --schema auto \
    --conf 0.35
```

### Step 3 — Manual label review (recommended)

Auto-labels are **never perfect**, especially for smoke. Spot-check (and fix)
a sample with [LabelImg](https://github.com/HumanSignal/labelImg) or
[Label Studio](https://labelstud.io):

```bash
pip install labelImg

# Always launch through the project's wrapper — never plain `labelImg`.
python scripts/labelimg.py train        # edit train split
python scripts/labelimg.py val          # edit val split
python scripts/labelimg.py test         # edit test split
```

In labelImg:

1. Switch the format toggle (left panel) to **YOLO**.
2. Use `A` / `D` to step frames, `W` to draw a new box, click a corner to drag,
   `Delete` to remove a box, `Ctrl+S` to save.

> ⚠ **Never run `labelImg` directly — always use `python scripts/labelimg.py`.**
> labelImg rewrites `classes.txt` on every save from its in-memory
> `label_hist`. Launched bare, `label_hist` starts empty and the next save
> truncates `classes.txt` to whatever subset of classes you've drawn this
> session — silently corrupting the schema and guaranteeing
> `IndexError: list index out of range` on the next image load.
>
> [scripts/labelimg.py](scripts/labelimg.py) (1) restores the canonical
> `classes.txt` from `configs/predefined_classes.txt` before launch and (2)
> passes the predefined file as the 2nd CLI argument so `label_hist` starts
> populated with the full 3-class list. Both files are written automatically
> by `src/dataset_builder.py` on dataset rebuilds.

### Step 4 — Build the dataset

The auto-label notebook ends by calling `dataset_builder.build_dataset(...)`,
which creates train / val / test splits **grouped by source video** (no leakage)
and emits `configs/dataset.yaml`. CLI equivalent:

```bash
python -m src.dataset_builder \
    --frames  data/frames \
    --labels  data/labels \
    --dataset data/dataset \
    --config  configs/dataset.yaml
```

### Step 5 — Train

```bash
python -m src.train          # 100 epochs, yolov8m, mosaic+mixup augmentation
```

Or step through `notebooks/training.ipynb` for live curves + a 20-image
prediction grid on the test split.

Best weights are copied to `models/best.pt` automatically.

### Step 6 — Real-time inference

```bash
# Webcam (live demo with FPS + ALERT overlay)
python -m src.inference --source 0

# Annotate a video file and save the result
python -m src.inference --source data/raw/mixed/roomfire41.mp4 --save

# Annotate a single image
python -m src.inference --source path/to/photo.jpg --save
```

Keyboard during video / webcam display:

| key | action |
|-----|--------|
| `q` | quit |
| `s` | save current annotated frame to `outputs/` |

CLI flags: `--conf 0.4 --iou 0.5 --weights models/best.pt --save --show / --no-show`.

## Expected performance

Target after 100 epochs on the supplied dataset:

* **mAP@0.5 > 0.75** for `person`
* **mAP@0.5 ≈ 0.6–0.75** for `fire`
* **mAP@0.5 ≈ 0.4–0.6** for `smoke` (smoke is the hardest class — improves
  most with manual label review)

For best results, collect more data — the supplied 24 videos are a starting
point, not a production-scale corpus.

## Notes

* All hardcoded thresholds (sample rate, blur, IoU, etc.) live as named
  constants at the top of each `src/*.py` module — easy to tune.
* `src/train.py` halves `--batch` on CUDA OOM and retries automatically.
* `dataset_builder.py` splits by source-video so frames from the same clip
  never appear in both train and val.
* Class schema is **decided automatically** — see `decide_class_schema` in
  `src/dataset_builder.py`.
