# Fire / Smoke / Person Detection — YOLOv8 Pipeline

Real-time detection of **fire**, **smoke**, and **people** in surveillance-style
video, powered by a fine-tuned **YOLOv8m** running on a CUDA GPU.

This project supersedes a classical-CV prototype (MOG2 + HSV thresholds + contours)
that lived previously in `Fire_Smoke_Detection.ipynb`. The preprocessing logic
from that notebook (video loading, frame inspection, colour-space EDA, blur
filtering) is retained in `notebooks/preprocessing.ipynb`. Everything from frame
sampling onwards now runs through a YOLOv8 stack.

---

## Pipeline at a glance

```
data/raw/          videos in fire/, smoke/, mixed/ subfolders
       │
       ▼  notebooks/preprocessing.ipynb  →  src/extract_frames.py
data/frames/       letterboxed 640×640 JPEGs, blurry + duplicate frames dropped
       │
       ▼  notebooks/auto_label.ipynb    →  src/auto_label.py
data/labels/       YOLO .txt labels per frame (COCO-person + HF fire-detector)
       │
       ▼  src/dataset_builder.py
data/dataset/      train / val / test split (75 / 15 / 10, grouped by source video)
configs/dataset.yaml
       │
       ▼  notebooks/training.ipynb      →  src/train.py
models/best.pt     fine-tuned YOLOv8m weights
       │
       ▼  src/inference.py  ·  app.py (Streamlit)
outputs/           real-time webcam, video, or single-image annotation
```

## What's NOT in the repo (and how to get it)

The following directories are intentionally git-ignored — they are either large,
user-supplied, or regenerable from the pipeline:

| path | what it holds | how to get it |
|---|---|---|
| `data/raw/` | source videos (fire / smoke / mixed) | See the [**Dataset**](#dataset) section below — two Kaggle sources combined into `data/raw/{fire,smoke,mixed}/` |
| `data/frames/`, `data/labels/`, `data/dataset/` | extracted frames + auto/manual labels + split | Regenerated by running `preprocessing.ipynb` → `auto_label.ipynb` |
| `runs/` | YOLOv8 training artifacts (checkpoints, plots, metrics) | Regenerated by `training.ipynb` / `python -m src.train` |
| `models/best.pt` | promoted best weights | Download from the [**weights-v1.0 Release**](https://github.com/7-lim/human-fire-smoke_detection/releases/tag/weights-v1.0) into `models/`, or retrain (step 5 below) |
| `outputs/` | annotated videos / snapshots / labeling reports | Regenerated by inference / labeling runs |
| `*.pt`, `*.onnx`, `*.engine` | any model weights | auto-downloaded (ultralytics) or built by training |

> **First-time setup order:** clone repo → install requirements → drop videos
> in `data/raw/` → run the 3 notebooks in order. The pipeline produces
> everything else.

## Dataset

The training corpus is **stitched together from two Kaggle datasets**. Neither
is redistributed in this repo — download them yourself and lay them out as
shown.

### Source 1 — Fire & Smoke Dataset (the 3 "mixed" videos)

**Link:** <https://www.kaggle.com/datasets/unidpro/fire-and-smoke-dataset>

Three full-scene videos with fire, smoke, **and** people in the frame
simultaneously. These live in `data/raw/mixed/`:

| file | content |
|---|---|
| `bucket11.mp4` | industrial bucket fire — white-hot flame, thin smoke |
| `roomfire41.mp4` | indoor room — calm scene then sudden flame + heavy smoke |
| `printer31.mp4` | office printer fire — dense smoke, people reacting |

### Source 2 — FireSense (per-class clips, `pos/` folders only)

**Link:** <https://www.kaggle.com/datasets/chrisfilo/firesense>

FireSense ships with separate fire/ and smoke/ folders, each split into
`pos/` (clips that contain the event) and `neg/` (control clips that
don't). For training a detector we only need the **positive** clips —
the negatives are useful for classifier evaluation, not for our YOLO use
case. We discard the `neg/` folders entirely.

| destination | source | count |
|---|---|---:|
| `data/raw/fire/` | FireSense `fire/pos/*.avi` | 11 videos |
| `data/raw/smoke/` | FireSense `smoke/pos/*.avi` | 13 videos |

### Final layout after both datasets are placed

```
data/raw/
├── fire/    11 .avi clips         ← FireSense fire/pos/
├── smoke/   13 .avi clips         ← FireSense smoke/pos/
└── mixed/   3 .mp4 clips          ← Fire & Smoke Dataset part1/2/3
```

Total: **27 source videos**. After extraction with the default sample rate
(every 10th frame, blur+dedup filtered, letterboxed to 640×640), this
produced **3,140 labeled frames** for the model used in this repo:

| split | images | fire boxes | smoke boxes | person boxes |
|---|---:|---:|---:|---:|
| train | 2,305 | 439 | 572 | 3,810 |
| val   |   576 | 511 | 266 |    21 |
| test  |   259 | 169 | 115 |    48 |

> The class schema (3-class fire/smoke/person vs merged 2-class
> fire_smoke/person) is **decided automatically** by
> `src/dataset_builder.decide_class_schema` from the fire-vs-smoke frame
> ratio after extraction. With the layout above the ratio is ~0.88 (in
> the balanced range), so the 3-class schema is chosen.

## Step-by-step usage

### Step 1 — Extract frames

Open `notebooks/preprocessing.ipynb` and Run All. It walks through video EDA
and then calls `src.extract_frames.extract_frames_from_dir(...)` to fill
`data/frames/`.

Or run it directly from the CLI:

```bash
python -m src.extract_frames \
    --input  data/raw \
    --output data/frames \
    --sample-rate 10
```

### Step 2 — Auto-label

Open `notebooks/auto_label.ipynb` and Run All. The notebook:

1. Decides 3-class vs merged 2-class schema (based on fire/smoke frame ratio).
2. Loads `yolov8m.pt` (COCO) + `betasecond/jimei-fire-smoke-yolo` (Hugging
   Face — classes `Fire` and `Smoke`). The model id originally in the spec
   (`keremberke/yolov8m-fire-detection`) was deleted from HF by its author;
   the replacement here exposes the same class schema.
3. Writes YOLO `.txt` files to `data/labels/`.
4. Plots class balance + confidence histogram.

CLI equivalent:

```bash
python -m src.auto_label \
    --frames data/frames \
    --labels data/labels \
    --schema auto \
    --conf 0.35
```

### Step 3 — Manual label review (recommended)

Auto-labels are **never perfect**, especially for smoke. Spot-check (and fix)
a sample with [LabelImg](https://github.com/HumanSignal/labelImg) or
[Label Studio](https://labelstud.io):

```bash
pip install labelImg

# Always launch through the project's wrapper — never plain `labelImg`.
python scripts/labelimg.py train        # edit train split
python scripts/labelimg.py val          # edit val split
python scripts/labelimg.py test         # edit test split
```

In labelImg:

1. Switch the format toggle (left panel) to **YOLO**.
2. Use `A` / `D` to step frames, `W` to draw a new box, click a corner to drag,
   `Delete` to remove a box, `Ctrl+S` to save.

> ⚠ **Never run `labelImg` directly — always use `python scripts/labelimg.py`.**
> labelImg rewrites `classes.txt` on every save from its in-memory
> `label_hist`. Launched bare, `label_hist` starts empty and the next save
> truncates `classes.txt` to whatever subset of classes you've drawn this
> session — silently corrupting the schema and guaranteeing
> `IndexError: list index out of range` on the next image load.
>
> [scripts/labelimg.py](scripts/labelimg.py) (1) restores the canonical
> `classes.txt` from `configs/predefined_classes.txt` before launch and (2)
> passes the predefined file as the 2nd CLI argument so `label_hist` starts
> populated with the full 3-class list. Both files are written automatically
> by `src/dataset_builder.py` on dataset rebuilds.

### Step 4 — Build the dataset

The auto-label notebook ends by calling `dataset_builder.build_dataset(...)`,
which creates train / val / test splits **grouped by source video** (no leakage)
and emits `configs/dataset.yaml`. CLI equivalent:

```bash
python -m src.dataset_builder \
    --frames  data/frames \
    --labels  data/labels \
    --dataset data/dataset \
    --config  configs/dataset.yaml
```

### Step 5 — Train

```bash
python -m src.train          # 100 epochs, yolov8m, mosaic+mixup augmentation
```

Or step through `notebooks/training.ipynb` for live curves + a 20-image
prediction grid on the test split.

Best weights are copied to `models/best.pt` automatically.

### Step 6 — Real-time inference

```bash
# Webcam (live demo with FPS + ALERT overlay)
python -m src.inference --source 0

# Annotate a video file and save the result
python -m src.inference --source data/raw/mixed/roomfire41.mp4 --save

# Annotate a single image
python -m src.inference --source path/to/photo.jpg --save
```

Keyboard during video / webcam display:

| key | action |
|-----|--------|
| `q` | quit |
| `s` | save current annotated frame to `outputs/` |

CLI flags: `--conf 0.4 --iou 0.5 --weights models/best.pt --save --show / --no-show`.

### Step 7 — Web demo (Streamlit)

[`app.py`](app.py) is a browser front-end over the same detector. It **reuses the
exact logic** from `src/inference.py` — the model, the per-class confidence
gates, the smoke area-filter and the ALERT thresholds — so what you see in the
browser matches `python -m src.inference`.

```bash
streamlit run app.py
# then open http://localhost:8501
```

Four tabs:

| tab | what it does |
|---|---|
| 🖼️ **Image** | upload a photo → input vs. annotated side-by-side, per-class counts, ALERT banner, download button |
| 🎞️ **Video** | upload a clip → frame-by-frame processing with a live progress bar + preview, then plays / downloads the annotated MP4 (capped by a *max frames* slider) |
| 📷 **Live webcam** | streams the **local machine's** webcam through the detector in real time, with a live ALERT/Clear status line |
| 🗂️ **Sample images** | pick from `data/dataset/images/test/` without uploading anything |

The sidebar exposes the device (auto-detects CUDA), the weights path, and the
NMS IoU / image-size sliders. It needs `models/best.pt` — train it (Step 5) or
grab the pretrained weights from the Release:

```bash
# Download the fine-tuned weights into models/
mkdir -p models
curl -L -o models/best.pt \
  https://github.com/7-lim/human-fire-smoke_detection/releases/download/weights-v1.0/best.pt
```

> **Note on the webcam tab:** `cv2.VideoCapture` opens the camera of the machine
> *running* Streamlit. Locally that's your own webcam. If you deploy this to a
> remote server it cannot reach a visitor's browser camera — use
> [`streamlit-webrtc`](https://github.com/whitphx/streamlit-webrtc) for that.

## Run with Docker (no local Python needed)

The Streamlit demo ships as a container so anyone with Docker can run it without
setting up Python, CUDA, or the dependency stack. The image uses a **CPU-only**
PyTorch build (avoiding the multi-GB CUDA wheels) — plenty for the image / video
/ sample-image tabs. Built size is ~3.5 GB (the torch + OpenCV + Jupyter stack);
dropping the notebook deps would trim it further.

### Prerequisites

* [Docker](https://docs.docker.com/get-docker/) (Desktop on Windows/macOS).
* The trained weights at **`./models/best.pt`** on the host — they are
  git-ignored and mounted into the container, *not* baked into the image. Grab
  them from the Release or train your own:

  ```bash
  # Linux/macOS
  mkdir -p models
  curl -L -o models/best.pt \
    https://github.com/7-lim/human-fire-smoke_detection/releases/download/weights-v1.0/best.pt
  ```
  ```powershell
  # Windows PowerShell
  New-Item -ItemType Directory -Force models | Out-Null
  curl.exe -L -o models/best.pt `
    https://github.com/7-lim/human-fire-smoke_detection/releases/download/weights-v1.0/best.pt
  ```

### One command (Docker Compose)

```bash
docker compose up --build      # build the image, then start the app
# open http://localhost:18501
docker compose down            # stop + remove when done
```

> **Why port 18501?** The container serves Streamlit on `8501` internally, but
> it's published on host port **18501**. On Windows the default `8501` often
> sits inside a Hyper-V/WSL-reserved range (`8491-8590`) and can't be bound.
> Override the host port with `APP_PORT`, e.g. `APP_PORT=8600 docker compose up`.

### Or with plain `docker`

```bash
docker build -t fire-smoke-detector .

# Linux/macOS  ->  open http://localhost:18501
docker run --rm -p 18501:8501 \
  -v "$(pwd)/models:/app/models:ro" \
  -v "$(pwd)/outputs:/app/outputs" \
  fire-smoke-detector
```
```powershell
# Windows PowerShell  ->  open http://localhost:18501
docker run --rm -p 18501:8501 `
  -v "${PWD}\models:/app/models:ro" `
  -v "${PWD}\outputs:/app/outputs" `
  fire-smoke-detector
```

### What's mounted, and why

| host path | container path | mode | purpose |
|---|---|---|---|
| `./models` | `/app/models` | read-only | the `best.pt` weights the app loads |
| `./outputs` | `/app/outputs` | read-write | annotated images / videos persist on the host |
| `./data` *(optional)* | `/app/data` | read-only | uncomment in `docker-compose.yml` to feed the **Sample images** tab |

### Notes & limits

* **Live webcam tab won't work in the container.** It uses Windows DirectShow
  (`CAP_DSHOW`) against the *host's* camera, which Docker can't reach. Use the
  Image / Video / Sample tabs, or run the webcam locally with
  `streamlit run app.py`.
* **GPU** is off by default (CPU torch). To use an NVIDIA GPU you need a
  CUDA-enabled torch build **and** the NVIDIA Container Toolkit (WSL2 on
  Windows); a ready-to-uncomment `deploy.resources` block is in
  `docker-compose.yml`.
* **Run the CLI inside the container** instead of the web UI, e.g.:
  ```bash
  docker compose run --rm detector \
    python -m src.inference --source configs/sample.jpg --save --no-show
  ```
* The container has a built-in **healthcheck** hitting Streamlit's
  `/_stcore/health`; `docker ps` shows `healthy` once it's ready.

## Expected performance

Target after 100 epochs on the supplied dataset:

* **mAP@0.5 > 0.75** for `person`
* **mAP@0.5 ≈ 0.6–0.75** for `fire`
* **mAP@0.5 ≈ 0.4–0.6** for `smoke` (smoke is the hardest class — improves
  most with manual label review)

For best results, collect more data — the supplied 24 videos are a starting
point, not a production-scale corpus.

## Notes

* All hardcoded thresholds (sample rate, blur, IoU, etc.) live as named
  constants at the top of each `src/*.py` module — easy to tune.
* `src/train.py` halves `--batch` on CUDA OOM and retries automatically.
* `dataset_builder.py` splits by source-video so frames from the same clip
  never appear in both train and val.
* Class schema is **decided automatically** — see `decide_class_schema` in
  `src/dataset_builder.py`.
